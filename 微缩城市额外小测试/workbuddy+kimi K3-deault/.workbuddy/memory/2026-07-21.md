## 性能优化（第二版，用户反馈卡顿）

**核心思路：draw call 从上万压到 ~150**
- 静态几何（道路/斑马线/车道线/建筑/公园/广场/灯杆/树）全部按颜色合批成少量大 BufferGeometry（`bucket` + `flushBucket`）
- 窗户：InstancedBufferGeometry + 自定义 ShaderMaterial，亮灯逻辑（bucket/onT/offT/模式权重）直接在 GPU fragment shader 计算，CPU 每帧只更新 2 个 uniform
- 红绿灯灯球：InstancedBufferGeometry + shader，按 uSimT uniform 在 GPU 里跑 6 态状态机
- 路灯/公园灯/警示灯：InstancedMesh
- 车辆 52 辆合并成 4 个大 BufferGeometry（车身顶点色/玻璃/前灯/尾灯），每帧重算顶点（绕 y 旋转 + 平移）
- 行人 20 人合并成 2 个 BufferGeometry（身体顶点色/头），同样每帧重算顶点
- 阴影：`shadowMap.autoUpdate=false`，手动隔 8 帧或太阳角度变化 >0.02 时才 needsUpdate
- pixelRatio 上限 1.5

**关键代码模式**：
- `addBox(color, x,y,z,w,h,d,rx,ry,rz)` → 进 bucket，最后 `flushBucket()` 合并
- 动态几何模板：`buildCarBuffer` 预分配空间 + `userData.perCar` 记录偏移，每帧 `updateCarGeometry` 重写 position/normal
- GPU 亮灯：窗户实例属性 iXf(pos+rotY) + iDat(rgb+bucket) + iDat2(onT+offT)，fragment 里算 `lit`

## Bug 修复（黑屏/一直"初始化中"）

**症状**：用户打开后屏幕全黑，HUD 显示"初始化中…"
**根因**：`flushBucket` 里假设所有几何体都有 `g.index`，但 `IcosahedronGeometry`（树冠）是**非索引几何体**，`g.index === null` → `g.index.count` 抛 TypeError 中断 init
**修复**：flushBucket 兼容非索引几何——无 index 时按顺序生成 0..N-1 索引
**验证**：headless Chrome (`--headless --disable-gpu --dump-dom`) 捕获 console error；修复后 canvas 创建成功、HUD 显示"窗户 22759 扇 · 绘制调用 291 次"、headless 截图确认城市完整渲染
**调试技巧**：`chrome --headless --disable-gpu --enable-logging=stderr --v=0 --virtual-time-budget=8000 --dump-dom <url>` 可无头捕获 JS 报错与 DOM 状态；`--screenshot` 截图验证渲染

**顺手加的调试参数**：URL hash `#t=22` 或 query `?t=22` 可指定初始时间

## 白天窗户表现优化（用户反馈黑窗不真实）

**问题**：白天未点亮窗户统一写成深蓝黑 `vec3(0.067,0.082,0.11)`，像黑洞，不符合现实
**方案**：窗户 fragment shader 重写——未亮窗颜色改为玻璃反射：
- 新增 uniform `uSkyTop`/`uSkyBot` 同步天空渐变色（每帧 `copy` skyUni）
- `vSeed` = 位置哈希生成每窗随机明暗（0.7~1.2，模拟窗帘/家具遮挡差异）
- `vFacing` = 朝向角 → `0.75+0.25*sin(facing+0.8)` 模拟东西向更亮、北向更暗
- 三种状态混合：`dayGlass = skyRef*0.95` / `duskGlass = skyRef*vec3(1,.75,.55)*0.55` / `nightGlass = 深蓝黑`，按 uModeW 加权
- 效果：白天窗户映出天空蓝灰、随朝向和随机明暗变化；黄昏带暖橙反光；夜晚才压成深玻璃

**验证**：headless dump-dom 确认 22759 窗、290 draw call、无 shader 编译错误
